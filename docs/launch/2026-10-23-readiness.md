## Security assessment

- **Server-only RLS model is safe as currently inspected.** All 42 public tables have RLS. The advisor's 34 `rls_enabled_no_policy` entries are INFO, not automatic vulnerabilities. Neither anon nor authenticated has public table-level privileges; anon has 41 vetted column SELECT grants across six content tables. No-policy/private tables deny client access. Prisma deliberately uses privileged server access, so application ownership, category scope and fresh session checks remain the enforcement boundary. No public views were found. Scheduler/trigger SECURITY DEFINER functions have fixed paths and deny anon/authenticated execution. The separate article/team policies above are actual defects in the permitted public subset.
- **Authentication and RBAC:** source and isolated tests cover bcrypt credential verification, account lockout, email-verified invitations, fresh role/active/ban reads, category scope, writer ownership, protected admin/editorial APIs, activation/deactivation, password-reset/session revocation and test-persona isolation. JWT sessions roll for 60 days, renew after one day and are invalidated after password changes through the credential stamp. Proxy checks supplement route-level guards. Production OAuth, cookie behaviour on actual phones and all role transitions on a hosted preview remain unverified.
- **CSRF:** NextAuth handles its own CSRF; the proxy rejects foreign Origin hosts for unsafe API methods. JSON endpoints and session cookies provide additional boundaries. Missing-Origin clients are permitted; there is no universal per-request CSRF token outside NextAuth. Unsubscribe currently mutates on a signed GET, so email-link scanners can consume it. A confirmation/POST redesign is optional follow-up; test that unsubscribe succeeds and repeats safely.
- **XSS:** article output is passed through a narrow tag/attribute/scheme allowlist; search highlights escape text; JSON-LD is safely serialized. Uploads reject SVG and sniff file bytes, enforce bucket roles and byte limits; article images are decoded with a pixel limit. CSP exists, removes production unsafe-eval, but still permits unsafe-inline. CSP nonces are a separate browser-tested improvement. There is no claim that sanitizer advisories are harmless simply because sanitization exists.
- **Rate limits:** per-instance maps prune expired entries. Account lockout persists in Postgres, while endpoint/IP budgets reset across instances. This is not a distributed abuse guarantee. The analytics 6,000/IP/minute ceiling is an abuse budget, not measured database capacity; 60/session+IP remains. Load tests intentionally disable limits; dedicated route tests exercise them.
- **Secrets:** only `.env.example` is tracked. A value-redacting current-tree scan found URL-like patterns in test fixtures only; no history/provider secret-store audit or production credential retrieval was performed. Test launches pin DB/storage/email locally, blank outbound-service keys and disable OAuth. Production key rotation and credential validation are outside scope. An anonymous published-article response is now explicitly projected to withhold internal editorial/engagement fields.
- **Dependencies:** scanner totals include development tools and transitive duplicates. The Auth.js email-provider normalization issue does not map directly to the configured Credentials + Google flow; the documented OAuth mix-up requires multiple OAuth providers, whereas this app configures one. The proxy catches malformed-token parsing errors. Native image-RCE applicability must account for the existing sharp override: local sharp 0.35.5 reports libvips 8.18.7 / libheif 1.23.5; this does not verify the deployed Linux binary. Windows/custom-server/next-og advisories are not automatically reachable here. RSC and image endpoints are exposed; Vercel-specific mitigations have not been verified. See [dependency evidence](evidence/dependency-audit.json), [Next image advisory](https://github.com/vercel/next.js/security/advisories/GHSA-2xp9-vwfh-vxw4), [image SSRF advisory](https://github.com/vercel/next.js/security/advisories/GHSA-cjq9-62q9-8jv4), and [Auth.js applicability](https://github.com/nextauthjs/next-auth/security/advisories/GHSA-x445-f3h2-j279).

## Publishing, scheduling and delivery

Production read-only evidence establishes an active `*/5` publisher, minute-by-minute reconciler and retained invocation outcomes. The SQL function targets the canonical HTTPS www endpoint with a dedicated Vault-backed publish credential. Over the observed 24 hours, all 288 invocations succeeded with zero warnings and zero due articles. A nonempty successful publication is recorded at **16 October 23:40 UTC**. No production scheduler request was triggered by this audit. Three recent independent GitHub health runs passed ([latest observed run](https://github.com/Zanie567/The-Consilium/actions/runs/39075221393)).

The isolated HTTP test creates a genuinely due scheduled article, calls the real route, confirms PUBLISHED/publishedAt/scheduledAt state, public rendering, one persisted notification and exactly one captured publication email, then replays the request and checks no duplicates. The complete writer-submit / editor-return / writer-resubmit / approve / public / unpublish path and cache freshness are also exercised. Compare-and-set publishing prevents concurrent duplicate side effects; notifications/email/achievements are subsequent operations, so a process crash after the publish commit can still leave missing side effects. There is no durable mail retry queue, provider-delivery webhook or guarantee of inbox delivery. Manual review mail similarly lacks a user-visible receipt on transport rejection. Keep an editor watching launch notifications.

**UK scheduling:** input is interpreted in Europe/London and stored as a UTC instant, independent of browser/server timezone. Regression checks prove **23 October 09:00 UK = 08:00 UTC (BST)** and **26 October 09:00 UK = 09:00 UTC (GMT)**. Spring's nonexistent hour is rejected; 25 October's repeated 01:30 resolves to the later GMT occurrence. Avoid ambiguous-hour scheduling unless this convention is explicitly intended. Cron's five-minute UTC cadence does not require a DST change.

**Duplicate-slug investigation:** production has zero duplicate slug groups. The unique index also reserves slugs on soft-deleted articles. Editing to another row's slug correctly returns 409 `SLUG_CONFLICT`; the local HTTP regression verifies the entire failed write rolls back, and saving again with the article's existing slug succeeds. Published slugs are deliberately locked; live factual changes use corrections. Concurrent creation still has a check-then-insert race, safely refused by uniqueness. Do not auto-rename an existing published URL to hide a collision. The production PostgreSQL log aggregate had zero unique-constraint events in its available 24-hour window; historic editing incidents were not reproduced or attributed conclusively. Capture a sanitized request ID/constraint name on recurrence; blanket P2002-to-slug messaging can misidentify a different unique constraint.

**Failure alerts:** unit/SQL tests cover overdue, stopped publisher, three failed calls, repeated warnings, blind monitoring, reminder deduplication and recovery. The GitHub workflow fails closed on unreadable/non-200 responses. GitHub scheduled workflows can run late; notification delivery depends on the responsible user's Actions email settings. The dedicated scheduler suite also passed 44 real-Postgres SQL/route tests: request construction, publication, reconciliation, warnings, alert thresholds, deduplication and recovery, with Vault/pg_net/pg_cron and email transport replaced locally. A green production health run proves the request/check path, not that a human received an alarm. Do not disable the publisher to test alerts in production; inject a failure in isolation and confirm a human-owned alert route separately.

## Traffic, analytics, SEO and public surfaces

The [scalability report](../performance/FRIDAY-2026-10-23.md) includes connection pooling, cache boundaries and the controlled ramp. Production uses a transaction pooler; the pg adapter's default is 10 connections per application instance, not the old URL `connection_limit` setting. The observed Postgres limit is 60; low current connection usage is not peak capacity. Personalized HTML remains private/no-store. Shared article-list data is tagged; publication invalidates after commit. Invalidation can fail; TTL is revalidation eligibility, not a hard outage staleness guarantee. Feeds use a **300-second** data TTL, while article lists use 30 seconds. Do not promise strict instantaneous RSS updates on a failed invalidation.

Article views deduplicate per session+article in **fixed 30-minute buckets**, not a rolling 30-minute unique-human count; a boundary crossing may count a fresh view sooner. Engagement uses a visit lock, monotonic cumulative active seconds, elapsed-time caps, a two-hour cap and consent-derived reader identity. Five-minute metrics distinguish visits from consented readers accumulating time across visits. Site views are per session+path+bucket, not unique site visitors. Estimated reading minutes from word count/progress and article read-length labels are estimates, distinct from measured foreground active time. Background tabs, blockers, closed-page beacon loss and cleared storage limit accuracy. A streamed HTML/RSC response can already have status 200 before a rendering error occurs; retry UI and render-body error checks are necessary alongside status codes. APIs explicitly return 503 on persistence/database failures. Isolated persistence tests cover concurrent replay, consent removal, hidden/draft exclusions, active-time bounding and editorial updatedAt preservation; local HTTP success alone is not the metric assertion.

The production sequential smoke checked 14 ordinary routes/assets at 200 and a deliberately missing URL at 404. It checked home, team, about, archive, categories, search/login shells, sitemap, RSS, robots and logo. CSP was present. Production had **zero non-trashed published articles**, so its RSS had zero items; a real production launch article, its structured data, images and all content links remain unverified. Search/login HTTP 200 is only shell availability. See [HTTP evidence](evidence/production-public-smoke.json).

Final controlled load run `next-e2e-3299-85843` completed **3,073 requests with zero HTTP/render errors**. It ramped mixed HTML/RSC to 100 simultaneous workers (p50/p95/p99 **366/1,541/1,644 ms**), then ran 1,960 paced reads across a 35-second cache-expiry interval (p95 **113 ms**). Same-article analytics at 100 workers had p95 **380 ms**; 528 repeated deliveries persisted **176 views, 176 view rows and 176 engagement sessions**, exactly the intended unique count. Sampled local peaks were 32 owned-database connections, four active sessions and two lock waiters. This is a short local closed-loop probe, with no browser assets under load or hosted pool/region limits. [Raw safe ramp evidence](evidence/local-release-ramp.json).

Local browser tests cover category membership/counts, public article bodies and images, internal-link HTML/RSC crawls, navigation, header/footer destinations, team dialogs, search, share controls, copy-link and reading progress. Dedicated device-sized checks inspect canonical/OG/JSON-LD, sitemap inclusion, RSS and decoded images. External social destinations are captured or inspected; no social post is sent. Actual Facebook/LinkedIn/iMessage previews, crawler cache refresh, mail-client handoff and the final editorial content require human checks. Newsletter registration persists and deduplicates subscriptions; signed unsubscribe is tested separately. There is no newsletter sending pipeline in the repository, welcome-email receipt or proof that an external sender includes unsubscribe links; the growth owner must verify the real distribution process before promising launch email delivery.

Vercel Hobby Instant Rollback reaches only the immediately previous eligible production deployment. It does not restore data/assets, reuses the target build's configuration/environment and reverts Vercel cron configuration. Supabase Cron is independent. After rollback Vercel suspends automatic domain assignment until rollback is undone. Check schema and credential compatibility first; do not assume every older build is recoverable.

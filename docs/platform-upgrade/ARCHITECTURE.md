## Complete publication lifecycle at audit base

1. Writer opens `/editorial/articles/new`; editor controller creates a DRAFT via `POST /api/articles` on first save. Untitled drafts are allowed. Writer cannot forge author or published status. Article/tags write atomically within a 15s transaction.
2. Content serialized as JSON string. Autosave/PATCH aliases PUT; local queue prevents concurrent create and protects dirty edits/in-flight status intent. No server optimistic revision compare exists: multiple browser tabs can overwrite one another. Do not claim conflict safety.
3. Writer PUT accepts only own DRAFT/REJECTED article. Submission changes to PENDING_REVIEW, clears editor feedback, sends category-editor/fallback notifications and email after save; notification/email failure does not falsely fail the committed save. Writer edits after submission/publish are rejected.
4. `/editorial/review/[id]` uses read-only Tiptap with inline editorial comments; editor opens edit route for document changes. ADMIN/EDITOR can edit subject to editor category scope. Stored inline comment positions plus quotes are verified/reanchored by existing code.
5. Review PATCH actions: approve/schedule/return require PENDING_REVIEW; unpublish/correct require PUBLISHED. Return→REJECTED; approve→PUBLISHED with date; schedule→SCHEDULED with future time; unpublish→DRAFT, clears publication/schedule/featured flags. Review status+notification is transactional; email is post-commit best effort. Source status check is outside write transaction: replay/race protection remains an audit risk.
6. Staff PUT additionally permits all statuses (including ARCHIVED) and direct publish, category/author changes, series and corrections; retain this established management path. Scheduling needs a stored/requested time. Cron bearer verification calls `publishScheduledArticles`, uses updateMany compare-and-set, publishes due articles, then best-effort notifications/email/achievements. Initial read excludes deleted rows, but compare-and-set omits deletedAt: concurrent trash race needs later integration fix.
7. Public article query requires PUBLISHED AND deletedAt=null; category/author/tag relations fetched; render JSON and sanitize HTML. Author/tag pages and lists retain URLs. Homepage intentionally excludes debate sides because dedicated debate panel displays them; category/archive must include them.
8. Published staff edits keep content live; unpublish makes it nonpublic; DELETE soft-deletes without changing status; restore clears deletedAt and therefore may immediately restore a published piece. Permanent trash delete is transactional with audit log; cron purges trash after 30 days. Related joins/comments/views cascade only on hard deletion. Article author FK does not cascade published content away; do not change that.

## Shared data contracts (binding)

### Formats and topics

- **Format = existing Category**. Initial main navigation: News/news, Opinion/opinion, Analysis/analysis. Existing Interviews/interviews/debates and public URLs remain supported; do not reclassify/delete existing rows. No new ArticleFormat enum/table. Drafts may have null category; enforce exactly one eligible primary category on submission/publication in later Discovery/integration work, without making old published null-category articles disappear.
- **Topic = existing Tag** (`id`, `name`, immutable published `slug`), ArticleTag composite `(articleId, tagId)`. No second taxonomy or array on Article.
- Canonical NEW names: strip markup, NFKC normalization, collapse internal whitespace, trim; identity case-insensitive. Canonical NEW slugs: lower-case, transliterate supported accents consistently, punctuation/ampersand become word separators, collapse hyphens, trim; examples in MASTER-SPEC required. One canonical helper in `articleTags.ts`, used by UI/API. Do not change this helper in parallel Editor work.
- Existing saved slugs are URLs, not recomputed display labels. Rename changes `name` only by default, retaining id/slug and all article links. Slug changes/merges need explicit redirect/alias migration proposal; not part of ordinary rename. Do not silently upsert a second tag because an old slug used different punctuation normalization. Discovery must reconcile legacy collision groups with a deterministic safe migration/preflight (no arbitrary row deletion).
- In-use tag deletion returns conflict; explicit reassignment/merge must be transactional and preserve article content. Existing DB cascade on Tag removes joins, not articles: server guard plus proposed FK RESTRICT prevents accidental stripping.
- Tag assignment has set semantics. Stable display order: normalized name, then id; no new join order column. Normal guidance 1–3, suggested curated set 5–10; current hard safety cap 25 is not the product target. Discovery owns final cap/validation and backward-compatible legacy edit policy.
- Public filtering: formats AND topics; topics OR (`tags.some.tag.slug.in`), use distinct parent query/count, no join duplicates. URL repeated `tag` parameters, normalized/deduped/sorted; `category`, `q`, `sort`, `page`; default sort publishedAt desc/nulls last then id. Reset page when filters change; same predicate for count/data; invalid page bounded. Canonical unfiltered listings and noindex/follow for combinations.
- Existing `/api/search` stays the search entry point. Preserve article fields while adding an additive response extension or coordinated UI change for typed author/topic results; do not break array consumers independently. Debounce, cancel stale requests, bounded queries and explicit errors. Reuse public visibility predicate.

### Rich content

- Persist **Tiptap/ProseMirror doc JSON as a string in Article.content**. No HTML storage replacement, JSONB migration, figure table, parallel Markdown store or blanket rewrite of old articles.
- `src/lib/richContent.ts` is the shared TypeScript contract, with `TiptapNode` compatibility export from articleRender. Attributes support JSON arrays (native table colwidth), not only primitive scalars. Types are not runtime validation; untrusted input remains unknown until validated.
- Native nodes remain `table`, `tableRow`, `tableHeader`, `tableCell`. Cell `colspan`, `rowspan`, `colwidth` preserve native semantics. Table metadata lives in table attrs, not unattached adjacent paragraphs: `caption`, `source`, `sourceUrl`, `note` (plain text except safe URL). No required metadata. Editor owns table extension and a public table renderer accepting a recursive child-render callback. Integrator wires that callback to the existing document render state so inline footnotes/links inside cells retain numbering and sanitization.
- Node `figure` stays atomic and backward compatible: existing `src`, `alt`, `caption`, `credit`; additive `source`, `sourceUrl`, `note`, `decorative`, `width`, `height`, `layout` (`standard`/`wide`/`centered`). Defaults preserve old nodes; metadata is plain text and output escaped; URLs http/https validated. Legacy `image` remains renderable. No custom chart builder; chart image uses figure.
- Figures owns extracted `FigureNode` and `figureRender.ts`; Editor owns parent editor/clipboard/table behaviours. Editor keeps asynchronous image paste but calls a Figures-owned adapter if needed; coordinate changes to upload contract before merge. Never register conflicting img parse rules or remove legacy image data.
- Public boundary: validate JSON shape/bounds, render escaped semantic HTML and pass through server `sanitizeArticleHtml`. Paste cleaner is a UX normalizer; it cannot replace that boundary. Review preview uses same node semantics and safe URL checks. Tables need allowlist tags/attrs plus sanitized bounded spans; allow no arbitrary styles/unsafe URLs. Integrator owns sanitizer/renderer dispatch changes so table/figure patches cannot erase each other's allowlists.
- Body CSS: Editor `editor.css` and Figures `figures.css`, imported once by integrator; Figures moves existing figure styling only where necessary. Parent globals.css controlled by integrator. No page-wide overflow; readable horizontally contained tables, aspect-safe images, no orphan labels.

### Analytics extension

Keep `/api/analytics/track` as the canonical collection endpoint; compatibility-map legacy view route so a page is counted once. Extend existing analytics portal/API, not a second dashboard. Preserve signed-in reading-position/read-through tooling and gamification separately.

Analytics owns proposed `ArticleEngagementSession` migration: id, articleId FK, optional consented pseudonymous reader key, startedAt/lastSeenAt, monotonic activeSeconds and engagedAt; no account FK or raw IP/browser fingerprint required. Unique visit/session key enables idempotent cumulative-heartbeat upsert; index article/time and optional reader/time. Views stay in ArticleView, do not double increment them on heartbeats. FK to Article cascades only on intentional hard article purge; no cascade to Article. RLS blocks public Data API access; all public events validate published article/limits server-side.

Metric contract: new visit/session per article, engagement qualifies once at >=300 **visible AND focused AND recently active** seconds. Monotonic timer; pause on hidden/blur, resume on activity; conservative 60s inactivity cutoff; no catch-up of inactive gaps. 30s cumulative heartbeat plus final visibility/pagehide flush; server clamps increments to elapsed time and caps session bounds; duplicate/out-of-order requests cannot add time twice. Idle reading remains an approximation and must be labelled. Average active time counts measured sessions, not inferred scroll minutes.

Returning reader: consented random identifier with finite retention (proposed 90 days, documented by Analytics), seen on an earlier UTC day in that window. Before acceptance/after decline, no persistent analytics identifier; anonymous session-only aggregate counting if privacy policy permits, otherwise no tracking. Do not claim current time-bucket hashes prove return visits: hash rotates with article/day bucket. Consent changes/removal must stop persistence. Analytics owns privacy text updates and precise metric definitions/evidence.

### Site settings and sharing

One runtime source for publication LinkedIn: existing `SiteSetting`, key `publication_linkedin_url`; Growth owns typed loader/admin validation. Absent/invalid setting hides link rather than generic LinkedIn fallback; real URL required from owner before release. Validate https LinkedIn publication destination, no credentials/control chars; all footer/navigation instances consume loader props, never DB imports in client components. No separate environment fallback for same setting. Existing commissioning/glossary keys remain intact.

Canonical production origin: explicit NEXT_PUBLIC_SITE_URL or known repository production domain `https://theconsilium.co.uk`, never inferred preview VERCEL_URL for public share links. Growth owns correcting canonical helper centrally; test environments explicitly set local origin. Site identity constants remain for compile-time values. Settings changes revalidate relevant layout/path if cached; uncached dynamic team data needs no invented cache tag.

**Integrator alone owns** `prisma/schema.prisma`, `prisma.config.ts`, migration namespace and ordering. Specialists provide SQL proposals/new-model patch in their status/owned migration proposal directory; integrator creates canonical timestamp migration files with installed Supabase CLI (`supabase migration new ...`) and updates Prisma model in one sequential commit per concept. Never introduce Prisma migrate deploy on an unmanaged history. Test both populated and empty LOCAL fixtures, migration replay, exact constraints, failure rollback, and introspect before/after. Analytics can begin pure timing/event/consent modules and its schema proposal from this foundation. Persistence code requiring generated Prisma models waits for the integrator's reviewed additive schema contract in the later integration assignment; do not use casts to pretend absent models exist. Discovery likewise submits canonical-name/FK/index changes before claiming DB-enforced guarantees. This is an explicit integration gate, not permission for either specialist to independently edit the schema.

New FKs match existing CUID text ids; use quoted camelCase Prisma fields unless an explicit @map requires snake_case; UUID only where existing model requires it. Profile existing FK cascades public card on account deletion but Article.authorId must retain restrict/no cascade. Join deletion can cascade from hard-deleted Article; deleting Tag must restrict active associations. Unique constraints enforce slug/profile/session identity; case normalization expression/index must match application function or use explicit canonical stored identity with a reviewed migration. Avoid unindexed reverse joins, unbounded ILIKE scans, N+1 and body fetches for cards. Full-text search/trigram is optional only if measured need, not automatic infrastructure scope.

## Known risks requiring explicit later ownership

- Discovery: tag historical normalization/slug aliases/name collisions; nullable format and taxonomy cap; costly content search and stale responses.
- Editor: table loss on public render, unsupported toolbar marks, unsafe paste boundaries, async selection race and preview parity; existing long headline field clipping at 375px observed in foundation inspection.
- Figures: missing metadata/editable alt; upload cap/collision/cancel/orphan/AVIF validation; reference-safe cleanup not proven.
- Team: linked chief/deputy placement, headings and deterministic id tie-break; legacy leadership exception; ADMIN linked-profile question is not an authorization enum change.
- Growth: real LinkedIn value absent; canonical preview fallback; newsletter concurrent duplicate race/labels, clipboard errors, provider/unsubscribe security must be preserved.
- Analytics: consent-gating gap, time estimates labelled active by implication, duplicate write endpoints, raw SQL column drift; no returning-reader evidence in current hashes.
- Integrator: revision conflict detection, review/scheduler concurrency, public GET data-selection privacy/internal author fields, missing historical migration history/indexes, tests with early returns, storage/email isolation. Two shell launchers formerly masked resolver failures through eval of empty command substitution; foundation now checks resolver status before eval. Preserve production boundaries and distinguish historical reports from fresh evidence.
